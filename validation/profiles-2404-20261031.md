# Ubuntu 24.04 dev / CI / cert validation

Completed: 2026-10-31T03:48:50.406728+00:00 (UTC). Instructions: [PROFILES.md](../PROFILES.md).

The three roles were built with `scripts/build-profiles.sh all`, using the
validated Ubuntu 24.04 ACT4 seed and a fresh pinned Ubuntu runtime. GCC and Spike
were not rebuilt. The cross-compiler binary SHA-256 is unchanged in every role.
Spike host debug sections were stripped; the full cross-toolchain and upstream
ACT4 checkout are retained. The prior integration image is unchanged.

## Behavior acceptance

- **dev:** the baseline passes; GDB multiarch recognizes `riscv:rv64`, loads the
  generated ELF and disassembles its actual entry point. The VS Code configuration
  parses and selects the dev image. No GUI session or live Spike remote-debug
  connection was tested.
- **ci:** a separate checkout at upstream parent commit
  `ac1923b5d2d43f2af159a17bcfda1e9989f66210` passes 51/51 and its actual revision is recorded.
  Changing that checkout's Spike command to stop after one instruction makes
  all 51 main tests fail and the host command exit 1. A changed `uv.lock` is
  rejected before building with stale dependencies.
- **cert:** only the sealed source is accepted; runtime file hashes are checked.
  The container root is read-only, work/data/key copies use writable tmpfs, and
  artifacts use the output mount. After 51/51 and the early-stop rejection, the
  artifact manifest is signed using an externally supplied local Ed25519 test
  key. Independent verification in another container validates the signature and
  all 325 recorded artifact entries.
- Altering the simulator revision input, overriding cert source, or changing a
  signed summary is rejected with exit 1. Selecting the wrong role image is
  rejected by the host wrapper.
- Six real-OpenSSL unit regressions cover valid signatures, changed content,
  hidden added content, changed manifests, wrong trusted keys and parent paths.
  ShellCheck and Python core Ruff rules E4/E7/E9/F pass.

## Curation findings and limits

The first slim run exposed UDB's Z3 dependency under the seed's cache directory.
Its native runtime artifacts were retained at `/opt/act4-cache` and included in
the sealed inventory. UDB generated data uses `/tmp/act4-data`; fixed libraries
and writable generated data are separate. These checks did not modify upstream
tests/generators or remove functional build dependencies to hide a failure.

This is a first 24.04 container-role matrix for the pinned RV64 I probe. It is not
a VM matrix, 26.04 role validation, full RVI20U64 coverage or official ACT
certification. The detached-manifest format and local signing identity are this
project's prototype; an ACT-approved release/signing policy still needs upstream
agreement. Ubuntu package repositories are not frozen. Prefix hashes and a
read-only root constrain the supplied workflow; host administrators/image
publishers remain trusted. No bit-identical rebuild or hostile-host security
claim is made.

# Ubuntu 24.04 ACT4 integration result

Date: 2026-10-24 (Asia/Shanghai).

The initial Phase 2 ACT4 integration passed the selected **51 RV64 I-suite test
ELFs**. This is a local environment integration result, not a complete RVI20U64
profile result or certification.

## Environment

- Existing Phase 1 Ubuntu 24.04 image:
  `sha256:b70edf2c2f8425fa45f7e2b438b4d5a3346e7b84b5c0b6937d3460ecdbdfc7db`.
- Existing GCC 16.2.0/Newlib reused without rebuilding GCC.
- ACT4 commit: `6da7a898d508fee6f741777840c05e71df561f0c`.
- Upstream configuration: `config/spike/spike-RVI20U64/test_config.yaml`.
- Selected extension suite: `I` only.
- Reference model: Sail 0.16, official release asset SHA-256 verified.
- ACT4 simulator: upstream CI-pinned Spike commit
  `2c300cd90eb74bb79f3fcdd58596a6f8d842d01c`, reporting `1.1.1-dev`, installed
  under `/opt/spike-act4` with its pinned SoftFloat submodule.
- Tools: mise 2026.10.18, Ruby 3.4.11, Bundler 4.0.23, uv 0.13.4,
  Python 3.14.8, and ACT4's Python/Ruby lock files.
- Normal test user: uid 1001. Container limits: 2 CPUs and 4 GiB memory.

The ACT4 tracked checkout remained unchanged after generation and testing.
Existing Phase 1 image tags and their image IDs were checked before and after.
The container's memory peak reached its 4 GiB cgroup limit, including page cache;
`oom` and `oom_kill` counters remained zero. This is not a host minimum-RAM claim.

## Results

| Check | Result |
|---|---|
| Generate and build selected upstream tests | 51 self-checking ELFs; success |
| Run all selected ELFs using the upstream runner | 51 passed; exit 0 |
| Disconnect container network, use a new output directory, rebuild and run | 51 passed; exit 0 |
| Deliberately stop one ELF after one simulated instruction | Upstream runner rejected missing success summary; exit 1, expected |
| Rerun original Phase 1 smoke test from preserved image, offline | PASS |

The build's `204 succeeded` message counts build-graph tasks, not 204 tests. Each
normal run executed 51 test ELFs. The offline run used already installed tools
and dependencies, but a fresh ACT4 output directory and new reference-model
signatures and self-checking ELFs.

The negative control did not modify a test's assertions. It changed only the
instruction budget for one existing ELF. Spike exited 0 without a success
summary; the upstream runner correctly returned 1 instead of accepting it.

## Compatibility finding

Phase 1 Spike v1.1.0 rejects `--instructions`, which the current upstream run
command uses. The Phase 2 experiment uses the exact revision in ACT4's
`.github/scripts/install-spike.sh` and preserves v1.1.0 in `/opt/spike`. No
simulator execution logic, upstream test assertions, or expected results were
patched.
